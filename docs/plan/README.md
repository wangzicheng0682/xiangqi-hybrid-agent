# Plan 规范

> 记录未成熟但打算去做的想法。所有AI可自由创建、更新、维护plan。

---

## 文档体系位置

```
CLAUDE.md (根目录) — AI开发入口
├── docs/DNA.md — 项目宪法（架构、模块、接口）
├── docs/STATE.md — 当前状态（进度、最近更新）
├── docs/plan/ — 记录未成熟想法（本文档）
└── docs/reference/ — 技术规范（标签、工具、API）
```

---

## 什么是Plan

**Plan** 是介于"想法"和"实现"之间的中间状态。

| 状态 | 说明 |
|------|------|
| 想法 | 脑子里的念头，未记录 |
| **Plan** | 已记录，有框架，待验证 |
| 实现 | 代码已落地，测试通过 |

---

## 命名规范

```
{序号}-{简短标题}.md
```

示例：
- `001-three-layer-prompt.md`
- `002-mcp-integration.md`
- `003-streaming-optimization.md`

序号使用三位数字，从001开始，按创建顺序编排，不随文档移动/删除而重新编号。

---

## 文档结构

每个Plan必须包含：

```markdown
# {标题}

## 背景
为什么有这个想法？要解决什么问题？

## 核心方案
具体打算怎么做？尽量详细。

## 待验证问题
有哪些不确定的地方需要验证？

## 预期收益
实施后能解决什么问题？

## 风险/阻碍
可能遇到什么困难？

## 状态
- [ ] 构思中
- [ ] 验证中
- [ ] 准备实现
- [ ] 已实现
- [ ] 已搁置/已废弃
```

---

## 状态流转

```
构思中 → 验证中 → 准备实现 → 已实现
                ↓
             已搁置
```

- **构思中**: 想法刚记录，框架未验证
- **验证中**: 正在分析可行性、寻找反例
- **准备实现**: 方案成熟，可以动手
- **已实现**: 代码已落地，更新文档链接
- **已搁置**: 暂时不做，记录原因

---

## 维护约定

1. **创建**: AI认为有价值记录的想法，立即创建plan
2. **更新**: 验证过程中有新发现，同步更新plan
3. **编号**: 序号永不复用，删除也不回收
4. **归档**: 已实现或已搁置的plan移动到 `_archived/` 子目录
5. **索引**: 本 README.md 的Plan列表保持最新
