# AI全栈开发开机/关机流程指南

## 版本: v3.0
## 创建日期: 2026-03-10
## 适用项目: 象棋AI混合代理教学与对弈系统

---

## 一、核心原则

### 1.1 文档驱动

本项目的开机/关机流程完全基于**文档和提示词**，无需任何自动化脚本。

**核心理念：**
- 文档即代码 - 所有状态都以文档形式存在
- 提示词即程序 - AI通过提示词理解并执行流程
- 人类在环 - 关键决策由人类确认

### 1.2 文件结构

```
xiangqi-hybrid-agent/
├── docs/
│   ├── STATE.md             # 当前状态（AI必读）
│   ├── REQUIREMENTS.md      # 产品需求
│   ├── ARCHITECTURE.md      # 技术架构
│   ├── ROADMAP.md           # 路线图
│   └── TRACEABILITY.md      # 可追溯矩阵
└── CLAUDE.md                # AI开发规范
```

## 二、开机流程

### 2.1 开机提示词模板

**复制以下提示词发送给AI：**

```
请执行AI全栈开发开机流程：

## 开机步骤

### Step 1: 读取状态文件
请读取 docs/STATE.md 了解项目当前状态

### Step 2: 确认当前任务
根据STATE.md，确认：
- 当前Sprint编号
- 当前阶段
- 待完成任务列表
- 任务优先级

### Step 3: 环境检查
检查以下环境项是否就绪：
- Python版本 >= 3.10
- 核心依赖已安装
- 引擎文件存在

### Step 4: 测试验证
运行 pytest -q 确认代码质量

### Step 5: 生成开机报告
汇总以上信息，生成开机状态报告

---

请按顺序执行，并在每一步完成后报告状态。
```

### 2.2 开机流程详解

#### Step 1: 读取状态文件

**文件读取目的：**

| 文件 | 用途 |
|------|------|
| STATE.md | 了解当前Sprint、已完成任务、待完成任务、服务状态 |

**AI读取指令示例：**
```
请读取 docs/STATE.md

读取后，请告诉我：
- 当前是哪个Sprint？
- 当前阶段是什么？
- 有哪些待完成任务？
- 任务优先级是什么？
```

#### Step 2: 确认当前任务

**任务确认模板：**
```
根据STATE.md，当前任务状态如下：

## 当前状态
- **Sprint**: Sprint 5
- **阶段**: 前后端联调完成
- **当前任务**: 功能验证与优化
- **优先级**: P0

## 待完成任务
1. [P1] PGN前端组件
2. [P0] 功能测试验证

请确认是否继续执行上述任务？
```

#### Step 3: 环境检查

**环境检查指令：**
```
请检查以下环境项：

1. Python版本
   命令: python --version
   要求: >= 3.10

2. 核心依赖
   命令: pip list | findstr fastapi
   要求: fastapi已安装

3. 引擎文件
   路径: data/engine/pikafish-avx2.exe
   要求: 文件存在

请报告每项检查结果。
```

#### Step 4: 测试验证

**测试验证指令：**
```
请运行以下命令验证代码质量：

pytest -q

如果测试失败，请：
1. 显示失败测试详情
2. 分析失败原因
3. 提出修复建议
```

#### Step 5: 生成开机报告

**开机报告模板：**
```markdown
## ✅ AI全栈开发环境开机完成

### 环境状态
| 项目 | 状态 |
|------|------|
| Python版本 | ✅ 3.12.x |
| 核心依赖 | ✅ 已安装 |
| 引擎文件 | ✅ 已就绪 |
| 测试状态 | ✅ xx passed |

### 当前任务
- **Sprint**: Sprint 5
- **阶段**: 前后端联调完成
- **任务**: 功能验证与优化
- **优先级**: P0

### 快速命令
```bash
# 启动后端
python -m uvicorn api.main:app --host 0.0.0.0 --port 8002

# 启动前端
cd frontend && npm run dev

# 运行测试
pytest -q
```

### 下一步
请告诉我您要执行的任务，我将开始开发。
```

## 三、关机流程

### 3.1 关机提示词模板

**复制以下提示词发送给AI：**

```
请执行AI全栈开发关机流程：

## 关机步骤

### Step 1: 检查未保存变更
检查是否有未保存的代码变更：
- 使用 git status 查看变更
- 列出所有修改的文件

### Step 2: 运行最终测试
运行 pytest -q 确保所有测试通过
- 如果测试失败，阻止关机
- 显示失败详情，要求修复

### Step 3: 更新状态文档
更新 docs/STATE.md：
- 记录本次会话完成的任务
- 更新待完成任务列表
- 更新最近会话记录

### Step 4: 更新追溯矩阵
更新 docs/TRACEABILITY.md：
- 添加新功能的追溯记录
- 更新功能状态

### Step 5: 生成关机报告
汇总本次会话成果，生成关机报告

---

请按顺序执行，门禁检查通过后才可关机。
```

### 3.2 关机流程详解

#### Step 1: 检查未保存变更

**变更检查指令：**
```
请检查未保存的代码变更：

git status

如果有变更，请：
1. 列出所有修改的文件
2. 询问是否保存变更
3. 如果保存，执行 git add 和 git commit
```

#### Step 2: 运行最终测试

**测试验证指令：**
```
请运行最终测试验证：

pytest -q

⚠️ 门禁要求：
- 如果测试失败，阻止关机
- 显示失败测试详情
- 要求修复后再关机
```

#### Step 3: 更新状态文档

**STATE.md 更新模板：**
```markdown
## 📝 最近会话记录

### 2026-03-10
**任务**: XXX
**完成**:
- 任务1
- 任务2

**下次任务**: 
1. 待完成任务1
2. 待完成任务2
```

#### Step 4: 更新追溯矩阵

**TRACEABILITY.md 更新模板：**
```markdown
| Feature | PRD Reference | TECH Reference | Code | Tests | Evidence | Status |
|---------|---------------|----------------|------|-------|----------|--------|
| {feature_name} | {prd_ref} | {tech_ref} | {code_path} | {test_command} | {evidence} | {status} |
```

#### Step 5: 生成关机报告

**关机报告模板：**
```markdown
## ✅ AI全栈开发会话结束

### 会话摘要
| 项目 | 内容 |
|------|------|
| 会话时长 | {duration} |
| 完成任务 | {completed_count} |
| 代码变更 | {changed_files_count} 文件 |
| 测试状态 | ✅ {test_count} passed |

### 已更新文档
- ✅ docs/STATE.md
- ✅ docs/TRACEABILITY.md

### 下次会话提示
下次开机时，AI将自动读取以下文件恢复状态：
- docs/STATE.md - 当前进度

### 待完成任务
1. {next_task_1}
2. {next_task_2}

---
**会话已安全结束，感谢使用！**
```

## 四、门禁机制

### 4.1 提交前门禁

**必须满足以下条件才能提交：**

```markdown
- [ ] pytest -q 全绿
- [ ] STATE.md 已更新
- [ ] TRACEABILITY.md 已更新（如有新功能）
```

### 4.2 关机前门禁

**必须满足以下条件才能关机：**

```markdown
- [ ] 所有测试通过
- [ ] STATE.md 已更新
```
