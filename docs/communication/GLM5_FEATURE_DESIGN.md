---

## 设计总原则：三句话

**第一句**：每个模式只服务一种用户心态，不强迫用户在错误的时机看错误的信息。

**第二句**：让「系统在思考」这件事可见，这是我们和所有竞争对手最大的差异。

**第三句**：演示时评委的眼睛应该永远知道该看哪里。

## 一、整体入口重设计

### 1.1 现在的问题

左侧边栏的五个模式是平级的，没有层次：
```
📊 分析模式
👥 双人对战  
🔴 执红对战
⚫ 执黑对战
📚 打棋谱
```

加入拍照识别之后，如果再加一个「📷 拍照识别」，就变成六个平级按钮，更乱。

### 1.2 重新分组：两个维度

所有功能按「输入方式」和「使用目的」分成两个维度：

```
┌─────────────────────────────────────────┐
│  🏯 象棋AI教练                           │
├─────────────────────────────────────────┤
│                                         │
│  ── 输入局面 ──────────────────────────  │
│                                         │
│  🖥️  在线对局        📷  拍照识别        │
│     网页棋盘上走棋       拍现实棋盘进入   │
│                                         │
│  ── 对局模式 ──────────────────────────  │
│                                         │
│  [📊 分析]  [🤖 人机]  [👥 双人]         │
│                                         │
│  ── 学习模式 ──────────────────────────  │
│                                         │
│  [📚 打棋谱]                            │
│                                         │
└─────────────────────────────────────────┘
```

「拍照识别」是一个**独立的入口**，不是某个模式的子功能。用户拍完照，识别成功后，可以选择进入「分析模式」或「人机对战」。

### 1.3 模式切换后的状态保持

模式切换时，棋盘上的局面**默认保留**，不重置。用户在「分析模式」分析了一个局面，切到「人机对战」，棋盘还在那里。只有用户主动点「重新开始」才清空。

这个细节在演示时很有用：可以先在分析模式讲解一个局面，再切到人机让评委体验。

## 二、YOLO 拍照识别——这是新的亮点功能

### 2.1 为什么这个功能格局不一样

其他所有功能都在数字世界里。拍照识别打破了这个边界——用户拿起手机，对着面前真实的棋盘拍一张，几秒后系统开始讲解。这个体验是「哦，它真的懂棋」的最强触发点。

比赛现场可以这样演示：桌上摆一盘真实的棋，拿出手机拍照，投影上出现识别结果，Agent 开始分析。这一幕的视觉冲击远大于任何网页操作。

### 2.2 功能流程设计

```
用户点击「📷 拍照识别」
        ↓
打开上传界面（两种方式）
  ┌─────────────┐  ┌─────────────┐
  │  📷 拍照    │  │  📁 上传图片 │
  │  调用摄像头  │  │  从相册选择  │
  └─────────────┘  └─────────────┘
        ↓
图片预览 + 「开始识别」按钮
        ↓
识别中（进度动画）
  「正在检测棋盘边界...」
  「正在识别棋子位置...」
  「正在生成 FEN...」
        ↓
    ┌───────────┬───────────────┐
    │ 识别成功  │   识别失败     │
    └───────────┴───────────────┘
         ↓                ↓
  棋盘预览确认界面    错误提示 + 重试
  「识别到 28 个棋子」
  「请确认棋盘方向」
         ↓
  [✓ 正确，开始分析]  [↺ 重新拍照]
  [⚙️ 手动校正]
         ↓
  选择下一步模式
  ┌──────────────┐  ┌──────────────┐
  │  📊 深度分析  │  │  🤖 人机对战  │
  └──────────────┘  └──────────────┘
```

### 2.3 识别结果确认界面（关键细节）

YOLO 不可能 100% 准确，必须给用户确认和校正的机会。确认界面设计：

```
┌──────────────────────────────────────────┐
│  识别结果确认                             │
├──────────────────┬───────────────────────┤
│                  │  识别信息              │
│   [棋盘预览]     │  ✓ 检测到棋盘         │
│                  │  ✓ 识别到 28 个棋子    │
│   识别到的棋子   │  ⚠️ 2 个棋子置信度较低  │
│   高亮显示       │                       │
│   低置信度棋子   │  棋盘方向              │
│   用橙色标出     │  [红方在下 ↓] [红方在上 ↑]│
│                  │                       │
│                  │  [手动校正棋子位置]   │
│                  │                       │
│                  │  [✓ 确认，开始分析]   │
└──────────────────┴───────────────────────┘
```

**低置信度棋子**（YOLO 不确定的）在棋盘预览上用橙色框标出，用户可以点击手动修改棋子类型。

### 2.4 手动校正功能

点击「手动校正棋子位置」进入校正模式：
- 点击棋盘上的任意位置，弹出棋子选择器
- 棋子选择器显示所有棋子类型，点击替换
- 支持「清除该位置棋子」
- 校正完成后返回确认界面

这个功能不需要做得很复杂，但必须有。否则 YOLO 一旦识别出错，整个流程就卡死了。

## 三、分析模式——演示主角，重点打磨

分析模式是比赛演示的核心，右侧面板必须最精心设计。

### 3.1 右侧面板结构

```
┌────────────────────────────────┐
│  [🏷️ 战术标签] [🧠 深度分析] [⚙️ 引擎] │  ← 三个标签页
├────────────────────────────────┤
│                                │
│  （标签页内容，见下方）          │
│                                │
└────────────────────────────────┘
```

### 3.2 「战术标签」标签页

在现有基础上加一个关键交互：**标签与棋盘联动**。

```
战术标签面板
├── ⚔️ 将杀困毙 (2)
│   ├── [被将军] ← hover 时棋盘上将/帅高亮
│   └── [将死]
├── 🎯 捉子层 (1)
│   └── [攻无根] ← hover 时棋盘画出攻击者→目标的连线
│              ← 攻击者和目标棋子高亮（攻击者红框，目标橙框）
└── 📊 局面分析
    ├── [中局阶段]
    └── [握有主动权]
```

具体实现：
- 标签 `hover` → 棋盘上相关棋子高亮 + 关系连线
- 标签 `click` → 效果持续固定，再次点击取消
- 连线样式：攻击关系用红色虚线箭头，防守关系用绿色虚线，牵制用橙色

这个联动让评委不需要自己在棋盘上找棋子，信息传达效率翻倍。

### 3.3 「深度分析」标签页——时间轴重设计

**这是最重要的改动。** 现在是日志滚动，改成时间轴。

视觉结构：

```
深度分析
─────────────────────────────────
[深度分析] 按钮（未开始时显示）

开始后：

  │ 10:23:41
  ●  🔍 扫描局面张力
  │
  ●  ⚡ 发现主要矛盾              ← 全宽金色卡片，稍大
  │  ┌────────────────────────┐
  │  │ 子力 vs 攻势失衡        │
  │  │ 红方多一象，黑方已渗入  │
  │  │ 核心问题：谁的计划更快？│
  │  └────────────────────────┘
  │
  ●  📚 检索知识库
  │  多子防守原则 → 「应主动兑换」
  │
  ●  🔧 调用工具                  ← 蓝色节点
  │  get_forcing_sequence
  │  原因：验证黑方最快将死线路
  │
  ●  📊 工具结果                  ← 绿色节点
  │  黑方最快需要 6 步
  │
  ●  ✅ 假设修正
  │  红方时间充足，局面未失控
  │
  ●  📝 生成讲解中...            ← 动画打字效果
  
─────────────────────────────────
讲解结果（流式输出）：
「当前局面的主要矛盾在于...」
```

**关键设计细节：**

`primary_contradiction` 消息 → 全宽金色卡片，字体稍大，有轻微的出现动画（从上方滑入）

`tool_call` 节点 → 蓝色圆点，旁边显示工具名和调用原因（这个「原因」字段要从后端传过来，参考 GLM5_COACH_INTELLIGENCE_GUIDE.md 里的设计）

`tool_result` 节点 → 绿色圆点，显示结果摘要，可以点击展开完整数据

时间轴是**流式出现的**，每个节点依次浮现，不是一次全部显示。这个动态效果本身就在传达「它在实时思考」。

## 四、人机对战模式——专注体验，减少干扰

### 4.1 右侧面板精简

对战时用户的注意力在棋盘上，右侧要尽量安静。

```
┌────────────────────────────────┐
│  走法记录                       │  ← 默认只显示这个
│  1. 炮二平五  马8进7            │
│  2. 马二进三  炮8平6            │
│  ...                           │
├────────────────────────────────┤
│  💡 开启提示    [关]            │  ← 切换开关
├────────────────────────────────┤
│  ← 这步棋之后才出现 →           │
│                                │
│  这步棋：良好 ✓                 │  ← 走完棋后出现的小卡片
│  [查看详细分析 ▾]               │  ← 点击才展开完整分析
└────────────────────────────────┘
```

走完棋后出现的「走法质量卡片」是关键设计：

```
┌─────────────────────────────────┐
│  炮二平五    良好 ✓              │
│  ─────────────────────────────  │
│  「当头炮开局，占据中路」         │  ← 一句话快速说明
│                                 │
│  [🧠 深度分析这步棋]             │
└─────────────────────────────────┘
```

默认只显示一句话评价，不打扰用户继续下棋。用户感兴趣了再点「深度分析」，这时右侧面板切换到完整的时间轴分析。

### 4.2 提示箭头的改进

现在已经有红色/蓝色箭头，建议加一个细节：

箭头旁边加一个极小的评分气泡（`+1.8`），让用户知道这步棋的价值，而不只是「这里可以走」。

## 五、打棋谱模式——叙事导向，每步有意义

### 5.1 走法列表加质量标注

走法记录列表改造：

```
走法记录
─────────────────────────────────
第 1 步    红方先行
1. 炮二平五                    ↗优
2. 马8进7                     → 良
─────────────────────────────────
第 2 步
3. 马二进三                    → 良
4. 车9平8                     ↘差  ← 红色，视觉吸引注意
─────────────────────────────────
```

「差」的走法用红色标出，吸引用户点击——用户会好奇「这步棋为什么差」，点击后右侧展开对这步棋的完整分析。这是打棋谱模式最自然的学习流程。

### 5.2 自动讲解开关

打棋谱模式新增一个开关：「自动讲解」。

开启后，每翻到下一步，系统自动触发对这步棋的快速分析（不是深度分析，1秒内），在右侧显示一句话解说。

```
自动讲解  [开 ●]

当前步：马8进7
「黑方跳马护中，同时准备出车，是屏风马的标准应对」
```

关闭后恢复手动模式，用户自己决定什么时候看分析。

## 六、棋盘本体的改进

### 6.1 走法高亮历史

走棋后，上一步的起点和终点在棋盘上保留淡色高亮（浅黄色背景），直到下一步棋走出。让用户随时能看到「刚才走了哪一步」。

这个功能你们可能已经有了，如果没有，优先级很高。

### 6.2 合法走法提示

用户点击一个棋子后，该棋子所有合法的落点用小圆点标出（现在不确定有没有实现）。这是基础功能，必须有。

### 6.3 棋子坐标标注（可选）

棋盘左侧和下方加上中国象棋的坐标标注（红方：一到九，黑方：１到９），帮助用户理解「炮二平五」这类标准记谱法。这个是加分项，不是必须的。

## 七、关于 YOLO 实现的技术建议

这部分写给开发同学，帮助判断方向。

### 7.1 权重来源

GitHub 上确实有象棋棋子识别的 YOLO 权重，搜索关键词：
- `chinese chess YOLO detection`
- `象棋 YOLOv8 棋子识别`
- `xiangqi piece detection`

找到权重后，主要需要微调的场景：
- 不同材质的棋子（木质、塑料、磁性）
- 不同角度拍摄（完全俯视 vs 稍有倾斜）
- 不同光线条件

### 7.2 识别流程的后端接口设计

```
POST /api/vision/recognize

Request:
  image: base64 或 multipart/form-data

Response:
{
  "success": true,
  "fen": "rnbakabnr/9/1c5c1/...",
  "confidence": 0.94,
  "pieces": [
    {
      "type": "红车",
      "position": [0, 0],
      "confidence": 0.98,
      "bbox": [x, y, w, h]  // 在原图中的位置，用于显示标注
    },
    {
      "type": "黑马",
      "position": [1, 7],
      "confidence": 0.71,   // 低于 0.8 视为低置信度，在前端用橙色标出
      "bbox": [x, y, w, h]
    }
  ],
  "board_bbox": [x, y, w, h],  // 棋盘在原图中的位置
  "orientation": "red_bottom"   // 识别到的棋盘方向
}
```

### 7.3 前端接收识别结果后的处理

```typescript
// 收到识别结果后
const handleRecognitionResult = (result: RecognitionResult) => {
  if (!result.success) {
    showError("识别失败，请重新拍照或调整光线");
    return;
  }
  
  // 低置信度的棋子需要用户确认
  const lowConfPieces = result.pieces.filter(p => p.confidence < 0.80);
  
  setRecognitionState({
    fen: result.fen,
    pieces: result.pieces,
    lowConfPieces,
    needsConfirmation: lowConfPieces.length > 0,
  });
  
  // 进入确认界面
  setCurrentView("recognition_confirm");
};
```

## 八、功能优先级总表

按比赛时间倒推，每项标注工作量估计：

### 必须在比赛前完成

| 功能 | 工作量 | 说明 |
|------|--------|------|
| 深度分析时间轴重设计 | 大（1-2天） | 演示核心，最优先 |
| 战术标签与棋盘联动 | 中（半天） | 信息展示效率关键 |
| YOLO 拍照识别完整流程 | 大（2-3天） | 新亮点功能 |
| 走法质量小卡片 | 小（2小时） | 对战模式体验 |
| 入口重新分组 | 小（2小时） | 解决「感觉乱」的根本 |

### 比赛前加分项

| 功能 | 工作量 | 说明 |
|------|--------|------|
| 打棋谱走法质量标注 | 小（2小时） | 学习模式体验 |
| 自动讲解开关 | 小（2小时） | 打棋谱沉浸感 |
| 走法高亮历史 | 极小（1小时） | 如果还没有的话 |
| 识别结果手动校正 | 中（半天） | YOLO 容错必须有 |

### 赛后完善

| 功能 | 说明 |
|------|------|
| 复盘报告生成 | 整局分析报告 |
| 三档讲解深度 | 初学者/进阶/教练 |
| 棋盘坐标标注 | 帮助理解记谱法 |

## 九、演示动线设计

加入 YOLO 之后，比赛演示可以有两条动线，视现场情况选择：

### 动线 A：纯数字（稳定，推荐保底）

```
开场介绍 → 走炮二平五 → 展示思考过程时间轴（主要矛盾出现）
→ 展示战术标签联动 → 指出「每句分析都有事实依据」 → 收尾
```

### 动线 B：拍照入场（冲击力强，需要提前准备好真实棋盘）

```
「我们的系统不只能分析数字棋局」
→ 拿出手机，对着桌上真实棋盘拍照
→ 投影显示识别过程动画
→ 「识别到 30 个棋子，置信度 96%」
→ 确认，进入分析
→ Agent 开始分析真实棋盘的局面
→ 思考过程时间轴流式出现
→ 「这就是连接现实棋盘的 AI 教练」
```

动线 B 的视觉冲击远大于 A，但需要：
- 赛前准备好一个有意思的真实棋局
- YOLO 识别稳定（低置信度棋子提前校正好）
- 桌上光线足够，棋盘方向摆正确

建议两条动线都准备，根据现场状态选择。

## 十、给你的一句话总结

加入 YOLO 之后，这个系统最强的演示节奏是：

**拍一张真实棋盘的照片 → 识别进系统 → Agent 识别出主要矛盾 → 时间轴里矛盾卡片出现 → 工具调用验证假设 → 教练式讲解输出**

这条链路端到端走通，从现实世界到 AI 分析，评委会觉得看到了真正有价值的东西。

所有前端设计都在服务这条链路。
