## 二、难点一：象棋规则精确实现

### 2.1 问题描述

中国象棋规则具有独特的复杂性，远超国际象棋：

**核心难点：**

| 难点 | 描述 | 技术挑战 |
|------|------|----------|
| 马腿检测 | 马的日字落脚点相邻位置有棋子时不能走 | 需准确判断相邻8个方向 |
| 象眼检测 | 象的斜线落脚中间位置有棋子时不能走 | 需判断象眼位置 |
| 九宫限制 | 仕/帅只能在己方九宫内移动 | 需精确边界判断 |
| 将帅照面 | 双方将帅不能在同一列上直接对面 | 需检测全列无子 |
| 自将过滤 | 走后导致己方将被攻击的走法非法 | 需将军检测 |
| 特殊棋子 | 兵/卒过河前后走法不同 | 需判断是否过河 |

### 2.2 解决方案

#### 技术方案：分层规则引擎

```python
    def _get_raw_moves(self, board: Board, row: int, col: int) -> List[Tuple[int, int]]:
```

#### 马腿检测实现

```python
KNIGHT_OFFSETS = [
    (-2, -1),  # 左上
    (-2, +1),  # 右上
    (-1, -2),  # 上左
    (-1, +2),  # 上右
    (+1, -2),  # 下左
    (+1, +2),  # 下右
    (+2, -1),  # 左下
    (+2, +1),  # 右下
]

def _get_knight_moves(self, board: Board, row: int, col: int) -> List[Tuple[int, int]]:
    """
    获取马的走法
    关键：检测马腿（leg_row, leg_col）
    """
    moves = []
    for dr, dc in KNIGHT_OFFSETS:
        # 马腿位置：落脚点的相邻格子
        leg_row, leg_col = row + dr // 2, col + dc // 2
        dest_row, dest_col = row + dr, col + dc

        # 检查马腿是否被挡
        if not self._is_valid(leg_row, leg_col):
            continue
        if board[leg_row][leg_col] is not None:  # 马腿被挡，跳过此方向
            continue

        # 检查落脚点是否有效
        if not self._is_valid(dest_row, dest_col):
            continue

        # 检查是否可以走（空位或敌方棋子）
        dest_piece = board[dest_row][dest_col]
        if dest_piece is None:  # 空位
            moves.append((dest_row, dest_col))
        elif dest_piece.color != board[row][col].color:  # 敌方棋子
            moves.append((dest_row, dest_col))

    return moves
```

#### 象眼检测实现

```python
ELEPHANT_OFFSETS = [
    (-2, -2),  # 左上
    (-2, +2),  # 右上
    (+2, -2),  # 左下
    (+2, +2),  # 右下
]

# 象的九宫限制
RED_PALACE = [(9,3),(9,4),(9,5),(8,3),(8,4),(8,5),(7,3),(7,4),(7,5)]
BLACK_PALACE = [(0,3),(0,4),(0,5),(1,3),(1,4),(1,5),(2,3),(2,4),(2,5)]

def _get_elephant_moves(self, board: Board, row: int, col: int) -> List[Tuple[int, int]]:
    """
    获取象的走法
    关键：检测象眼（eye_row, eye_col）+ 九宫限制
    """
    moves = []
    piece = board[row][col]
    is_red = piece.color == 'red'

    for dr, dc in ELEPHANT_OFFSETS:
        # 象眼位置：中间的斜线格子
        eye_row, eye_col = row + dr // 2, col + dc // 2
        dest_row, dest_col = row + dr, col + dc

        # 检查象眼是否被堵
        if not self._is_valid(eye_row, eye_col):
            continue
        if board[eye_row][eye_col] is not None:  # 象眼被堵
            continue

        # 检查落脚点是否在己方半场
        if not self._is_valid(dest_row, dest_col):
            continue
        if (dest_row, dest_col) not in (RED_PALACE if is_red else BLACK_PALACE):
            if is_red and dest_row < 5:  # 红象不能过河
                continue
            if not is_red and dest_row > 4:  # 黑象不能过河
                continue

        # 检查是否可以走
        dest_piece = board[dest_row][dest_col]
        if dest_piece is None:
            moves.append((dest_row, dest_col))
        elif dest_piece.color != piece.color:
            moves.append((dest_row, dest_col))

    return moves
```

#### 自将过滤实现

```python
def _is_valid_move(self, fen: str, from_pos: Tuple[int, int], to_pos: Tuple[int, int]) -> bool:
    """
    验证走法是否合法
    关键：走后不能导致己方将被攻击
    """
    # 1. 执行走法获取新FEN
    new_fen = self.make_move(fen, from_pos, to_pos)

    # 2. 检查新局面下己方是否被将军
    # 注意：使用_raw_moves（攻击范围）而非legal_moves
    # 因为攻击范围不考虑自将（否则会循环）
    king_pos = self._find_king(new_fen, self._get_turn(fen))
    enemy_attacks = self._get_all_attacks(new_fen, opponent=True)

    # 3. 如果己方将被在敌方攻击范围内，走法非法
    if king_pos in enemy_attacks:
        return False

    return True
```

#### 将帅照面检测

```python
def _kings_face_each_other(self, fen: str) -> bool:
    """
    检测将帅是否照面（在同一列上直接对面）
    """
    red_king = self._find_king(fen, 'red')
    black_king = self._find_king(fen, 'black')

    # 将帅必须在同一列
    if red_king[1] != black_king[1]:
        return False

    # 检查中间是否有其他棋子
    col = red_king[1]
    for row in range(red_king[0] + 1, black_king[0]):
        if self._get_piece(fen, row, col) is not None:
            return False

    return True

def _can_move_king_face(self, fen: str, from_pos: Tuple[int, int], to_pos: Tuple[int, int]) -> bool:
    """
    验证将帅走法是否会导致照面
    """
    new_fen = self.make_move(fen, from_pos, to_pos)
    return not self._kings_face_each_other(new_fen)
```

## 三、难点二：LLM幻觉防护

### 3.1 问题描述

通用大语言模型在象棋分析中会产生严重的"幻觉"问题：

**幻觉类型：**

| 类型 | 表现 | 危害 |
|------|------|------|
| 棋子位置幻觉 | 描述不存在的棋子 | 严重误导 |
| 战术关系幻觉 | 编造保护/攻击关系 | 分析错误 |
| 走法规则幻觉 | 给出违反规则的走法 | 不可信 |
| 评估分数幻觉 | 给出不符合引擎的评估 | 误导学习 |

**典型案例：**
```
用户：这步棋怎么样？
LLM：红车威胁黑马，因为黑马没有其他棋子保护。
真相：黑马实际上有黑炮保护 → LLM幻觉
```

### 3.2 解决方案

#### 方案概述：Evidence Map约束机制

```

│                     传统方案：LLM自由发挥                         │
├─────────────────────────────────────────────────────────────────┤
│  FEN ──▶ LLM ──▶ 分析结果（幻觉风险）                            │
│           ↑                                                     │

│                     本项目方案：Evidence Map约束                  │
├─────────────────────────────────────────────────────────────────┤

```

```python
def _build_structured_evidence_map(self, fen: str) -> Dict[str, Any]:

    作为LLM的事实锚点
    """

    tags = self._detect_all_tags(fen)

    # 2. 张力检测
    tensions = self._detect_tensions(fen, tags)

    # 3. 阶段判断
    phase = self._detect_phase(fen)

    # 4. 引擎评估
    engine_eval = self._query_engine(fen)

    return {
        "fen": fen,
        "tags": [

                "bind_pieces": tag.bind_pieces,  # 棋子坐标
```

```python
def get_piece_defenders(fen: str, piece: str) -> ToolResult:
    """
    查询棋子保护关系
    用于验证LLM的假设
    """
    # 1. 解析FEN
    board = parse_fen(fen)

    # 2. 找到目标棋子
    target_pos = find_piece(board, piece)

    # 3. 遍历所有己方棋子
    defenders = []
    for row in range(10):
        for col in range(9):
            piece = board[row][col]
            if piece and piece.color == board[target_pos].color:
                # 检查是否攻击目标位置
                attacks = get_raw_moves(board, row, col)
                if target_pos in attacks:
                    defenders.append(piece)

    return ToolResult(
        success=True,
        data={
            "piece": piece,
            "defenders": [f"{p.color}{p.type}-({p.row},{p.col})" for p in defenders],
            "count": len(defenders)
        },
        message=f"{piece}被{len(defenders)}个棋子保护"
```

## 四、难点三：真Agent模式设计

### 4.1 问题描述

大多数"AI象棋"是硬编码流程，LLM只是被动回答：

**传统方案：**
```
用户：分析这个局面
系统：调用LLM
LLM：输出固定格式的分析（LLM不知道该用什么工具）
结果：LLM的分析浮于表面，缺乏深度
```

**问题：**
- LLM不知道该调用什么工具
- 工具调用是预设的，不是LLM自主决策的
- 无法像教练一样主动验证假设

### 4.2 解决方案

#### Function Calling架构

```python
class AgentTools:
    """
    LLM可调用的工具集
    设计原则：原子化、可组合、结构化返回
    """

    # 工具元数据
    TOOL_META = {
        "get_piece_attacks": {
            "description": "获取棋子攻击范围",
            "when_to_use": [
                "当你想知道某个棋子能攻击什么时",
                "当你分析'这步棋威胁了什么'时",
                "当你验证棋子间关系时"
            ],
            "parameters": ["fen", "piece"]
        },
        "get_piece_defenders": {
            "description": "查询棋子保护关系",
            "when_to_use": [
                "当你想知道谁在保护某个棋子时",
                "当你评估'被攻击的棋子是否有保护'时"
            ],
            "parameters": ["fen", "piece"]
        },
        # ... 其他工具
    }

    def __call__(self, tool_name: str, arguments: Dict) -> ToolResult:
        """统一工具调用入口"""
        if tool_name not in self._tool_functions:
            return ToolResult(success=False, message=f"Unknown tool: {tool_name}")

        try:
            result = self._tool_functions[tool_name](**arguments)
            return result
        except Exception as e:
            return ToolResult(success=False, message=str(e))
```

#### LLM自主决策循环

```python
class BaseExpert:
    def analyze(self, fen: str, ...) -> ExpertResult:
        """
        Agent分析循环
        LLM自主决定调用哪些工具，最多3轮
        """

        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": f"分析这个局面：{fen}"}
        ]

        tool_call_count = 0
        max_tool_calls = 3

        while tool_call_count < max_tool_calls:
            # 1. LLM决定是否调用工具
            response = llm.chat(messages, tools=self.tool_schemas)

            if response.tool_calls:
                # 2. 执行工具
                for tool_call in response.tool_calls:
                    tool_result = self.tools(tool_call.name, tool_call.arguments)

                    # 3. 记录到消息历史
                    messages.append({
                        "role": "assistant",
                        "content": "",
                        "tool_calls": [tool_call]
                    })
                    messages.append({
                        "role": "tool",
                        "tool_call_id": tool_call.id,
                        "content": tool_result.json()
                    })

                tool_call_count += 1
            else:
                # 4. LLM输出最终分析
                break

        # 5. 生成最终报告
        final_response = llm.chat(messages)
        return ExpertResult(finding=final_response.content)
```

#### 证据裁决合成器

```python
class Synthesizer:
    """
    证据裁决合成器
    不是简单的文本合并，而是证据裁判
    """

    def synthesize(self, expert_results: List[ExpertResult]) -> SynthesisResult:
        # 1. 收集所有结构化断言
        all_claims = []
        for result in expert_results:
            all_claims.extend(result.claims)

        # 2. 按来源分类和排序
        tool_verified = [c for c in all_claims if c.source == "tool_verified"]
        reasoning = [c for c in all_claims if c.source == "reasoning"]
        unverified = [c for c in all_claims if c.source == "unverified"]

        # 3. 交叉验证（检查矛盾）
        validated, conflicts = self._cross_validate(
            tool_verified + reasoning
        )

        # 4. 按权重裁决
        final_claims = []
        for claim in validated:
            if claim.source == "tool_verified":
                weight = 1.0
            elif claim.source == "reasoning":
                weight = 0.7
            else:
                weight = 0.3

            final_claims.append(WeightedClaim(claim, weight))

        # 5. 生成教练式讲解
        explanation = self._generate_explanation(final_claims)

        # 6. 输出证据基础
        evidence_base = self._format_evidence_base(validated, conflicts)

        return SynthesisResult(
            explanation=explanation,
            claims=final_claims,
            evidence_base=evidence_base,
            confidence=self._calculate_confidence(final_claims)
        )
```

#### 证据交叉验证

```python
def _cross_validate(self, claims: List[Claim]) -> Tuple[List[Claim], List[Conflict]]:
    """
    交叉验证断言
    检测矛盾并裁决
    """
    validated = []
    conflicts = []

    for i, claim1 in enumerate(claims):
        for claim2 in claims[i+1:]:
            # 检查是否矛盾
            if self._is_contradicting(claim1, claim2):
                conflicts.append(Conflict(claim1, claim2))

                # 裁决：高置信度胜出
                if claim1.confidence > claim2.confidence + 0.2:
                    validated.append(claim1)
                elif claim2.confidence > claim1.confidence + 0.2:
                    validated.append(claim2)
                else:
                    # 置信度相近：都保留，标记矛盾
                    claim1.marked_conflict = True
                    claim2.marked_conflict = True
                    validated.extend([claim1, claim2])
            else:
                validated.extend([claim1, claim2])

    return validated, conflicts
```

#### 折射效果实现

```glsl
// ===== Pass 4: mainPass - 折射 + 色散 + 菲涅尔 =====
// fragment-main.glsl

// 法线计算
vec2 calcNormal(vec2 p) {
    float eps = 0.001;
    vec2 dx = vec2(eps, 0.0);
    vec2 dy = vec2(0.0, eps);

    float dfdx = sdf(p + dx) - sdf(p - dx);
    float dfdy = sdf(p + dy) - sdf(p - dy);

    return normalize(vec2(dfdx, dfdy));
}

// 折射采样（色散效果）
vec4 sampleRefracted(vec2 uv, vec2 normal) {
    // RGB三通道不同折射率
    float refractionR = 0.98;
    float refractionG = 1.00;
    float refractionB = 1.02;

    vec2 offsetR = normal * u_refraction * refractionR;
    vec2 offsetG = normal * u_refraction * refractionG;
    vec2 offsetB = normal * u_refraction * refractionB;

    float r = texture2D(u_blurredBg, uv + offsetR).r;
    float g = texture2D(u_blurredBg, uv + offsetG).g;
    float b = texture2D(u_blurredBg, uv + offsetB).b;

    return vec4(r, g, b, 1.0);
}

// 菲涅尔效应
float calcFresnel(vec2 p, vec2 normal) {
    float fresnel = 1.0 - abs(dot(normal, vec3(0.0, 0.0, 1.0)));
    fresnel = pow(fresnel, 3.0);
    fresnel = clamp(fresnel, 0.0, 1.0);
    return fresnel;
}

// 主渲染
void main() {
    // SDF距离
    float d = sdfMain(v_texCoord);

    if (d > 0.0) {
        // 形状外：透明
        gl_FragColor = vec4(0.0);
        return;
    }

    // 计算法线
    vec2 normal = calcNormal(v_texCoord);

    // 采样折射背景
    vec4 refracted = sampleRefracted(v_texCoord, normal);

    // 菲涅尔效果
    float fresnel = calcFresnel(v_texCoord, normal);
    vec3 fresnelColor = mix(vec3(0.0), u_fresnelColor, fresnel);

    // 高光
    vec3 specular = pow(max(dot(reflect(vec3(0.0, 0.0, 1.0), vec3(normal, 0.0)),
                              lightDir), 0.0), 32.0) * u_specularStrength;

    // 组合最终颜色
    vec3 finalColor = refracted.rgb + fresnelColor + specular;

    // 边缘渐隐
    float edgeFade = smoothstep(0.0, -2.0, d);
    gl_FragColor = vec4(finalColor, edgeFade * u_opacity);
}
```

```glsl
// ===== Pass 2-3: 高斯模糊 =====
// fragment-bg-vblur.glsl (竖向)

precision highp float;

uniform sampler2D u_texture;
uniform vec2 u_resolution;
uniform float u_blurRadius;

void main() {
    vec2 uv = gl_FragCoord.xy / u_resolution;
    vec4 color = vec4(0.0);
    float total = 0.0;

    // 竖向9-tap高斯
    float blurSteps[9] = float[](-4.0, -3.0, -2.0, -1.0, 0.0, 1.0, 2.0, 3.0, 4.0);

    for (int i = 0; i < 9; i++) {
        float offset = blurSteps[i] * u_blurRadius / u_resolution.y;
        float weight = exp(-0.5 * blurSteps[i] * blurSteps[i] / 4.0);

        color += texture2D(u_texture, uv + vec2(0.0, offset)) * weight;
        total += weight;
    }

    gl_FragColor = color / total;
}
```

```typescript
class SSEClient {
    private eventSource: EventSource | null = null;
    private listeners: Map<string, Function[]> = new Map();

    connect(url: string) {
        this.eventSource = new EventSource(url);

        // 监听所有事件类型
        this.eventSource.addEventListener('thinking', (e) => {
            this.emit('thinking', JSON.parse(e.data));
        });

        this.eventSource.addEventListener('expert_result', (e) => {
            const data = JSON.parse(e.data);
            this.emit(data.expert, data);
            this.emit('expert_result', data);
        });

        this.eventSource.addEventListener('expert_step_content', (e) => {
            const data = JSON.parse(e.data);
            this.emit('step_content', data);
        });

        this.eventSource.addEventListener('synthesis_chunk', (e) => {
            const data = JSON.parse(e.data);
            this.emit('synthesis', data);
        });

        this.eventSource.addEventListener('result', (e) => {
            this.emit('result', JSON.parse(e.data));
            this.disconnect();
        });

        this.eventSource.addEventListener('error', (e) => {
            this.emit('error', e);
            this.disconnect();
        });
    }

    on(event: string, callback: Function) {
        if (!this.listeners.has(event)) {
            this.listeners.set(event, []);
        }
        this.listeners.get(event)!.push(callback);
    }

    emit(event: string, data: any) {
        const callbacks = this.listeners.get(event) || [];
        callbacks.forEach(cb => cb(data));
    }

    disconnect() {
        if (this.eventSource) {
            this.eventSource.close();
            this.eventSource = null;
        }
    }
}
```

### 9.1 核心技术创新

| 创新点 | 描述 | 突破 |
|--------|------|------|
| Evidence Map约束 | 规则引擎→事实锚点→LLM表达 | 解决LLM幻觉问题 |
| 真Agent模式 | LLM自主决策工具调用 | 从硬编码流程到自主智能 |
| 证据裁决合成 | 工具验证→交叉验证→权重裁决 | 从文本合并到证据推理 |
| 阶段感知思维 | 开局/中局/残局差异化分析 | 专业化象棋分析 |
| 自适应专家 | 根据张力数量选择专家组合 | 效率与深度平衡 |
| RAG知识检索 | ChromaDB向量检索+棋理原则索引 | AI知识支撑 |

### 9.2 工程创新

| 创新点 | 描述 | 突破 |
|--------|------|------|
| 45标签检测体系 | 覆盖所有战术类型的规则检测 | 全面性+准确性 |
| 张力检测器 | 自动识别局面矛盾 | 智能分析驱动 |
| WebGL液态玻璃 | 四步渲染管线+物理光学 | Apple级视觉效果 |

| 三级难度对弈 | easy/medium/hard深度配置 | 适应不同水平 |
