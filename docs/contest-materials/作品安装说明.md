| 软件 | 版本要求 | 用途 | 下载地址 |

## 二、快速安装（约5分钟）

### Step 1: 克隆项目

```bash
git clone <项目仓库地址>
cd xiangqi-hybrid-agent
```

### Step 2: 安装Python依赖

```bash
python -m venv venv
venv\Scripts\activate.bat
pip install -r requirements.txt
```

> 依赖包括：FastAPI、uvicorn、chromadb、openai、pydantic、numpy等

### Step 3: 安装前端依赖

```bash
cd frontend
npm install
cd ..
```

### Step 4: 配置环境变量

在项目根目录创建 `.env` 文件：

```bash
# ─── LLM API 配置 ───
# 阿里云DashScope（通义千问）示例
ALIYUN_API_KEY=your_api_key_here
ALIYUN_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1

# ─── 模型选择 ───
COACH_MODEL=qwen-plus           # 教练Agent使用的模型
EXPERT_MODEL=qwen-plus          # 三专家使用的模型
SYNTHESIZER_MODEL=qwen-plus     # 合成器使用的模型

# ─── 并发控制 ───
LLM_MAX_PARALLEL_REQUESTS=4     # LLM并发请求数（默认4）

# ─── 引擎配置 ───
PIKAFISH_PATH=data/engine/pikafish.exe
PIKAFISH_DEPTH=20               # 默认分析深度

# ─── 向量数据库 ───
RAG_PERSIST_DIR=data/chroma_db  # ChromaDB本地持久化目录

# ─── Neo4j（可选）───
# NEO4J_URI=bolt://localhost:7687
# NEO4J_USER=neo4j
# NEO4J_PASSWORD=password
```

> **关于API Key**：系统支持任何OpenAI兼容API，包括阿里云通义千问、智谱GLM-5等。只需配置 `ALIYUN_API_KEY` 和 `ALIYUN_API_BASE`。

## 五、后端模块启动流程

后端采用惰性初始化设计，各模块按需启动：

```
api.main:app 启动
    │
    ├── [即时] 路由注册（11+端点）
    ├── [即时] CORS中间件
    │
    ├── [首次请求时] TacticalDetector
    │   └── 加载45个标签定义 + 规则引擎初始化
    │
    ├── [首次请求时] TensionDetector
    │   └── 6种张力类型定义
    │
    ├── [首次请求时] EnginePool（单例）
    │   └── 启动Pikafish子进程（~200ms）
    │   └── 双重检查锁保证线程安全
    │
    ├── [首次深度分析时] MultiAgentOrchestrator
    │   ├── ReliableLLMClient（信号量+熔断器）
    │   ├── 三专家实例化
    │   └── Claim解析器
    │
    ├── [首次知识检索时] ChromaDB
    │   └── 加载/创建向量索引
    │   └── 索引80+棋理原则（首次约2-3秒）
    │
    └── [可选] Neo4j连接
        └── 棋谱图数据库（需单独启动Neo4j服务）
```

**设计用意**：首次冷启动后，后续请求均走热缓存路径，无额外初始化延迟。

## 六、关键配置说明

### 6.1 LLM并发控制

系统使用 `BoundedSemaphore` 限制LLM并发请求数，避免API限流：

```
LLM_MAX_PARALLEL_REQUESTS=4
```

- 设为2：安全保守，适合免费API额度
- 设为4：推荐值，多专家并行性能最优
- 设为1：极限保守，强制串行化执行

### 6.2 引擎深度配置

```
PIKAFISH_DEPTH=20    # 默认分析深度
```

深度与对弈难度的映射关系：
| 难度 | 深度 | 特点 |
|------|------|------|
| 入门(easy) | 4层 | 偶尔犯错，适合初学者 |
| 进阶(medium) | 10层 | 中等水平 |
| 高手(hard) | 18层 | 接近满强度 |

### 6.3 模型配置

三个模型配置项可以分别指定不同模型：

```
COACH_MODEL=qwen-plus          # 快速分析的教练Agent
EXPERT_MODEL=qwen-plus         # 深度分析的三专家
SYNTHESIZER_MODEL=qwen-plus    # 合成器
```

可选模型：`qwen-plus`、`qwen-max`、`glm-5`、`deepseek-chat` 等（需对应API配置）。

## 七、常见问题

### Q1: 引擎提示"pikafish.exe not found"
确认 `data/engine/pikafish.exe` 存在，或修改 `.env` 中的 `PIKAFISH_PATH`。

### Q2: LLM调用失败，返回超时
检查 `.env` 中的 `ALIYUN_API_KEY` 是否有效。系统内置熔断器（连续12次失败自动熔断），恢复后会自动重试。

### Q3: 前端启动报错
确认Node.js版本 ≥ 18，删除 `frontend/node_modules` 后重新 `npm install`。

### Q4: ChromaDB初始化慢
首次启动需索引80+条棋理原则，约需2-3秒。后续启动会读取本地持久化缓存。

### Q5: 端口被占用
后端默认8002，前端默认3001。可通过启动命令的参数修改：
```bash
# 后端改用8003端口
python -m uvicorn api.main:app --host 0.0.0.0 --port 8003

# 前端改用3002端口
cd frontend && npx vite --port 3002
```
