# 设计思路

## 一、问题分析

### 1.1 象棋AI分析的核心问题

象棋作为中国传统智力游戏，具有独特的规则体系和战术复杂性。一个优秀的象棋AI分析系统需要解决以下核心问题：

#### 问题1：规则精确性

中国象棋规则复杂度远超国际象棋：

| 规则要素 | 国际象棋 | 中国象棋 | 复杂度差异 |
|----------|----------|----------|------------|
| 马的走法 | 日字走法 | 日字走法+马腿检测 | 中国象棋多马腿限制 |
| 象的走法 | 斜线走法 | 斜线走法+象眼限制 | 中国象棋多象眼限制 |
| 将帅位置 | 全棋盘 | 限九宫 | 中国象棋多九宫限制 |
| 将帅关系 | 王不见王 | 王不见王+照面 | 中国象棋多照面规则 |
| 兵/卒位置 | 有两种兵 | 过河前后不同走法 | 中国象棋多过河规则 |

**技术挑战：**
- 马腿检测：马的落脚点相邻位置有棋子时不能走
- 象眼检测：象的落脚点中间位置有棋子时不能走
- 九宫限制：仕/帅只能在己方九宫内移动
- 将帅照面：双方将帅不能在同一列上直接对面（中间无子）

#### 问题2：LLM幻觉问题

通用大语言模型在象棋分析中容易产生"幻觉"：

**幻觉类型：**
1. **棋子位置幻觉** - 描述不存在的棋子或位置
2. **战术关系幻觉** - 编造保护/攻击关系
3. **走法规则幻觉** - 给出违反规则的走法
4. **评估分数幻觉** - 给出不符合引擎的评估

**危害程度：**
- 普通用户无法识别幻觉内容
- 错误的分析会误导学习者
- 严重影响系统的可信度

#### 问题3：专业性表达

象棋分析需要专业知识和表达方式：

**术语体系：**
- 开局原则：出子效率、中心控制、先手争夺
- 中局战术：先手、后手、牵制、闪击、抽将
- 残局技术：王手、困毙、必胜、谋和

**知识深度：**
- 经典杀法：马后炮、铁门栓、双车错、卧槽马
- 战略定式：中炮对屏风马、顺手炮、列手炮
- 残局定式：单车胜双士、炮单士象胜单将

#### 问题4：缺乏专业知识支撑

**现状：** 通用LLM缺乏象棋领域的专业知识支撑：
- 不知道经典杀法名称和适用条件
- 不了解开局定式的战略意图
- 无法引用经典棋谱作为参考

**解决方案：** RAG知识检索系统
- 索引80+棋理原则（开局/中局/残局）
- 索引14万局棋谱开局信息
- 支持语义检索，按阶段/类型过滤

### 1.2 现有方案的局限性

#### 传统象棋引擎

**代表：** Stockfish、Pikafish、象棋巫师

**优点：**
- 计算精确，评估客观
- 走法推荐准确

**缺点：**
- 只输出评分和走法，不解释原因
- 输出专业术语，初学者难以理解
- 无法提供个性化的学习指导

#### 通用大语言模型

**代表：** GPT-4、Claude、GLM

**优点：**
- 自然语言表达流畅
- 可以解释棋理

**缺点：**
- 象棋规则理解不精确
- 棋子位置描述容易"编造"
- 战术关系判断不准确

#### 混合方案（其他尝试）

**代表：** Chess.com Analysis、lichess analysis

**做法：** 引擎+LLM简单拼接

**缺点：**
- LLM仍然产生幻觉
- 缺乏深度的棋理分析
- 无法像教练一样讲解

## 二、技术选型

### 2.1 核心设计决策

#### 决策1：规则引擎 vs 机器学习模型

| 方案 | 准确性 | 可解释性 | 开发成本 | 维护成本 |
|------|--------|----------|---------|----------|
| 机器学习模型 | 依赖训练数据 | 黑盒 | 高 | 高 |
| 规则引擎 | 100%精确 | 白盒 | 中 | 低 |
| **混合方案（本项目）** | **100%精确** | **白盒** | **中** | **低** |

**选择理由：**
- 象棋规则是确定的，适合用规则引擎
- 规则引擎的判定100%准确，无模型幻觉
- 可解释性强，便于调试和优化
- 开发成本可控，维护成本低

#### 决策2：特征提取方式

| 方案 | 实现方式 | 准确性 | 泛化能力 |
|------|----------|--------|----------|
| 神经网络提取 | 训练CNN/RNN | 中等 | 强 |
| **规则脚本提取** | **硬编码规则** | **100%** | **有限** |
| 混合提取 | 规则+模型 | 高 | 中 |

**选择理由：**
- 规则脚本准确性100%，无幻觉风险
- 每个标签绑定具体棋子坐标，可验证
- 对于已知的战术模式，规则提取完全覆盖

#### 决策3：LLM的角色定位

**错误做法：** 让LLM重建棋盘空间（产生幻觉）

**正确做法（本项目）：**
- LLM只负责"表达层"（教练式讲解）
- 规则引擎负责"事实层"（精确检测）
- Evidence Map作为桥梁连接两层

## 四、核心模块设计

### 4.1 标签检测体系

#### 设计目标
- 100%规则硬判定，无模型幻觉
- 每条标签绑定具体棋子坐标
- 置信度二元化（0或1）

#### 标签分类

**1. 将杀困毙层（3个）**
```python
# 检测函数：_detect_check_mate_stalemate()
is_check          # 被将军：将军检测
is_checkmate      # 将死：无可用合法走法
is_stalemate      # 困毙：无可用合法走法但未被将军
```

**2. 捉子层（3个）**
```python
# 检测函数：_detect_capture()
is_attack_unprotected    # 攻无根：攻击无保护棋子
is_mutual_attack         # 互吃：双方互相威胁对方棋子
is_attack_king_adjacent  # 攻将邻：攻击将帅相邻位置
```

**3. 闪击抽将层（3个）**
```python
# 检测函数：_detect_discovered_attack()
is_discovered_check       # 闪将：移动棋子后露出将军
is_double_attack_with_check # 抽将：将军的同时抽子
is_discovered_attack       # 闪击：移动后露出攻击
```

**4. 牵制串打层（2个）**
```python
# 检测函数：_detect_pin_skewer()
is_pinned              # 被牵制：移动会暴露将帅
is_cannon_double_attack # 炮串打：一炮穿两子
```

**5. 标准杀法层（8个）**
```python
# 检测函数：_detect_standard_mate()
checkmate_horse_back_cannon    # 马后炮
checkmate_iron_gate            # 铁门栓
checkmate_double_rook          # 双车错
checkmate_horse_corner        # 卧槽马
checkmate_bare_king           # 白脸将
checkmate_double_cannon_battery # 重炮杀
checkmate_sea_bottom_moon     # 海底捞月
checkmate_side_tiger          # 侧面虎
```

#### 检测算法核心

```python
class TacticalDetector:
    def detect_all_tags(self, fen: str) -> TagDetectionResult:
        """主检测入口"""
        board = self._parse_fen(fen)

        results = []
        results.extend(self._detect_check_mate_stalemate(board))
        results.extend(self._detect_capture(board))
        results.extend(self._detect_discovered_attack(board))
        results.extend(self._detect_pin_skewer(board))
        results.extend(self._detect_standard_mate(board))
        results.extend(self._detect_piece_status(board))
        results.extend(self._detect_semantic(board))

        return [r for r in results if r.detected]
```

### 4.2 张力检测器

#### 设计目标
- 自动识别局面中的矛盾和异常
- 驱动分析方向（选择哪些专家）
- 为LLM提供分析切入点

#### 张力类型

| 张力类型 | 检测条件 | 分析价值 |
|----------|----------|----------|
| 评估异常 | \|cp\| > 300 且 tactical_count < 2 | 引擎与标签矛盾 |
| 子力vs攻势 | 子力占优但对方有攻势 | 攻防策略冲突 |
| 危机中的资源 | has_check AND (has_unprotected OR has_initiative) | 危中有机 |
| 沉睡的棋子 | 有价值高但活跃度低的棋子 | 子力未发挥 |

        all_claims = []
        for result in expert_results:
            all_claims.extend(result.claims)

        # 2. 按来源分类
        tool_verified = [c for c in all_claims if c.source == "tool_verified"]
        reasoning = [c for c in all_claims if c.source == "reasoning"]
        unverified = [c for c in all_claims if c.source == "unverified"]

        final_claims = self._weight裁决(validated)

        # 5. 生成教练式讲解
        explanation = self._generate_explanation(final_claims)

            claims=final_claims,

### 7.1 LLM调用可靠性

```python
class ReliableLLMClient:
    """统一LLM可靠性客户端"""

    def __init__(self):
        self.semaphore = Semaphore(max_parallel)
        self.breaker = CircuitBreaker(fail_max=5, reset_timeout=60)

    def complete(self, messages: List[Dict]) -> str:
        """带重试和熔断的LLM调用"""

        # 1. 获取信号量
        with self.semaphore:
            # 2. 检查熔断器
            if self.breaker.is_open:
                raise CircuitBreakerOpen()

            # 3. 指数退避重试
            for attempt in range(max_retries):
                try:
                    response = self._call_api(messages)
                    self.breaker.record_success()
                    return response
                except (RateLimitError, ServerError):
                    wait = backoff ** attempt
                    sleep(wait)
                except Exception:
                    self.breaker.record_failure()
                    raise
```
