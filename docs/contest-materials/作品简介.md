# 作品简介：象棋AI混合代理教学与对弈系统

---

## 一、作品定位与核心命题

### 1.1 一句话定义

**让AI像教练一样读懂棋局、讲解棋局——而不是念坐标。**

本系统是一个面向象棋学习者的智能教学平台，核心创新在于：**用确定性规则引擎提取100%准确的棋局事实，再用大语言模型将事实转化为教练级讲解**。这一"事实层+表达层"的双层架构，从根本上解决了通用LLM分析棋局时的幻觉问题。

### 1.2 解决的核心问题

中国象棋AI领域长期存在一个断层：**引擎算得清但说不明白，LLM说得好听但编造事实**。现有方案各有致命缺陷：

| 现有方案 | 能力 | 致命缺陷 |
|----------|------|----------|
| 传统引擎（Stockfish/Pikafish） | 计算精确，评分权威 | 只输出数字评分和最佳走法，不解释"为什么这步好" |
| 通用LLM（GPT-4/GLM-5） | 自然语言表达流畅 | 会编造棋子位置、伪造攻防关系、违反特殊规则（马腿、象眼） |
| 引擎+LLM简单拼接 | 引擎评分+LLM翻译 | LLM仍然在翻译过程中引入幻觉，无法验证自身输出的正确性 |

**我们的系统填补了这个断层**：规则引擎做"事实裁判"，LLM做"教练表达"，Evidence Map做"事实锚点"——三者协同实现零幻觉的教练式讲解。

### 1.3 设计理念

> "设计，为专注而生。"

我们的界面设计遵循一个核心信念：**真正的好设计，是让用户忘掉界面的存在，完全沉浸在象棋的世界里。** 摒弃冗余炫酷，回归体验本质。以空间感构建界面秩序，用材质差异划分信息层级，降低认知负担，让注意力回归棋局本身。

```
│    ↓          │                    │    ↓                              │

│ 引擎评估      │                    │    ↓                              │
│ 张力检测      │                    │ Phase 2: 自适应专家调度           │
│    ↓          │                    │   战术专家 / 战略专家 / 引擎专家  │
│ 结构化结果    │                    │    ↓                              │
└──────────────┘                    │ Phase 3: 证据裁决合成             │
                                    │   Claim交叉验证 → 教练式综合讲解  │
                                    │    ↓                              │
                                    │ Phase 4: SSE流式推送到前端        │
                                    └──────────────────────────────────┘
```

## 三、技术架构

### 3.1 四层分离架构

```
┌─────────────────────────────────────────────────────────────────────┐
│  呈现层：React 18 + TypeScript + WebGL Liquid Glass                │
│  棋盘（深墨棋谱盘） / 专家卡片动画 / Evidence灵动岛 / SSE消费     │
└─────────────────────────────────┬───────────────────────────────────┘
                                  │ REST + SSE
┌─────────────────────────────────▼───────────────────────────────────┐
│  接口层：FastAPI（异步 + SSE原生支持）                              │
│  11+端点 / 请求验证 / 流式管理 / CORS                              │
└─────────────────────────────────┬───────────────────────────────────┘
                                  │
┌─────────────────────────────────▼───────────────────────────────────┐
│  事实层：确定性规则引擎（100%准确，零幻觉）                         │
│  45标签检测器 / 6张力检测器 / 规则引擎 / Pikafish / 开局库          │
│  输出 → Evidence Map（结构化事实锚点）                              │
└─────────────────────────────────┬───────────────────────────────────┘
                                  │ Evidence Map 约束
┌─────────────────────────────────▼───────────────────────────────────┐
│  表达层：LLM多Agent系统（教练式讲解）                               │
│  14个Agent工具 / 3专家并行 / Claim证据裁决 / 合成器 / RAG          │
└─────────────────────────────────────────────────────────────────────┘
```

**架构核心原则**：LLM永远不直接"观察"棋盘。所有棋盘事实——棋子位置、攻防关系、走法合法性——必须经由规则引擎提取，通过Evidence Map传递给LLM。LLM只负责"基于已验证事实的表达"，不负责"事实发现"。这一原则从架构层面杜绝了LLM幻觉。

### 3.2 技术栈

| 层级 | 技术选型 | 选择理由 |
|------|----------|----------|
| 前端框架 | React 18 + TypeScript + Vite | 组件化生态成熟 + 极速HMR开发体验 |

| 向量数据库 | ChromaDB | 纯Python轻量部署，无外部服务依赖 |

| LLM | GLM-5 / 通义千问（可配置） | 中文能力强 + Function Calling原生支持 |

## 五、核心创新点

### 创新一：Evidence Map零幻觉架构（核心创新）

**问题**：通用LLM分析象棋时会编造棋子位置（"红车在5路"实际在3路）、伪造攻防关系（"黑马无根"实际有炮保护）、违反特殊规则（忽略蹩马腿）。

**方案**：建立"事实层→Evidence Map→表达层"的单向信息流。规则引擎以100%准确率提取棋局事实（45个战术标签+棋子坐标绑定），形成结构化Evidence Map作为不可篡改的"事实锚点"。LLM收到的System Prompt中明确规定："任何具体棋子的坐标或位置、任何走法的具体效果、任何引擎评估数值，只能来自Evidence Map或工具返回"。当LLM需要验证某个推断（如"红车是否被保护"），必须调用`get_piece_defenders`工具获得事实，不允许凭感觉判断。

**效果**：系统输出的每一个棋子位置、每一段攻防关系、每一个走法评估，都有规则引擎或工具调用的事实支撑，从架构层面杜绝幻觉。

### 创新二：真Agent工具调用模式

**问题**：传统方案是"硬编码分析管线+LLM翻译"，分析维度固定，LLM无法自主探索感兴趣的方向。

**方案**：14个原子化工具通过OpenAI Function Calling协议暴露给LLM，LLM像教练一样自主决定"先看什么、再查什么"。例如发现"黑马被牵制"后，LLM可能自主调用`get_threats_to_piece`确认威胁来源，再调用`simulate_move`推演解除牵制的后果。candidate_id协议确保LLM只能使用规则引擎生成的合法走法，不能自行编造UCI走法。

### 创新三：三专家并行协同+证据裁决合成

**问题**：单一分析视角容易遗漏信息，自由文本合并容易引入矛盾。

**方案**：战术/战略/引擎三个专家Agent独立分析同一局面，各自输出结构化Claim断言（每个Claim包含statement、source、confidence、evidence四要素）。合成器不是简单拼接文本，而是按证据权重裁决：工具验证的Claim优先于推理，推理优先于未验证。当高权重Claim之间存在矛盾时，合成器必须明确标注分歧并解释原因。

### 创新四：自适应调度+开局快答路径

**问题**：所有局面统一走重型三专家链路，开局简单局面也消耗大量LLM资源。

**方案**：门控式调度策略基于问题关键词、张力数量（≥3触发全团队）、博弈阶段、手数等多维度自适应选择专家组合。开局前6-8手命中定式时启用快答通道，仅调用轻量战略+引擎专家，直接利用开局库和原则库生成快答，响应时间从秒级降至亚秒级，同时前端仍展示完整的"轻量专家→协调者综合"演出层。

### 创新五：WebGL Liquid Glass物理光学渲染

**问题**：传统CSS `backdrop-filter: blur()` 无法实现真实的光学折射效果。

**方案**：自研4遍WebGL渲染管线（背景采样→垂直高斯模糊→水平高斯模糊→折射合成），在最终Pass中实现物理级折射（IOR可调）、色散（RGB三通道不同偏移量模拟色散效应）、菲涅尔边缘反射（pow(1.0+merged, 5.0)指数模型）、定向炫光。所有光学参数通过Leva面板实时调节，参数自动持久化。

### 创新六：SSE流式多专家思考可视化

**问题**：深度分析耗时多秒，用户等待期间缺乏反馈，不知道AI在做什么。

**方案**：后端通过`queue.Queue`+`threading.Thread`+`StreamingResponse`实现SSE事件流。每个专家的启动、思考步骤、工具调用、发现结论、合成步骤，都作为独立事件实时推送。前端专家卡片翻转动画（K♥战术/J♠战略/Q♦引擎）、Evidence灵动岛（4阶段调度脉冲+实时工具轨迹）、协调者综合面板协同呈现完整分析过程，让用户"看到AI在想什么"。
