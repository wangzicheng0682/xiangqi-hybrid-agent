# 象棋AI混合代理教学与对弈系统 - 设计书

---

## 一、项目概述

### 1.1 项目名称
象棋AI混合代理教学与对弈系统（Xiangqi Hybrid Agent Teaching & Playing System）

### 1.2 项目定位
**核心目标**：让AI像教练一样读懂棋局、讲解棋局，而不是念坐标

**用户群体**：
- 象棋学习者（教学讲解）
- 棋谱研究者（历史对局分析）
- 比赛选手（复盘分析）

### 1.3 核心价值
- **零幻觉分析** - 基于规则的事实检测，置信度100%
- **教练式讲解** - 基于事实的因果分析，不是念坐标
- **双模式响应** - 快速模式<1秒 / 深度模式3-5秒（SSE流式）

## 二、技术架构

### 2.1 技术栈

| 层级 | 技术 | 用途 |
|------|------|------|
| **前端** | React 18 + TypeScript + Vite + Tailwind CSS | 现代化UI，Liquid Glass效果 |
| **后端** | FastAPI + Python 3.10+ | RESTful API + SSE流式响应 |
| **引擎** | Pikafish (Stockfish衍生) | 零漏算评估 |
| **符号系统** | 45个战术标签 + 张力检测器 | 事实层精确计算 |
| **LLM** | Qwen-Max (阿里云百炼) | 讲解生成，Function Calling |
| **知识库** | Neo4j + RAG | 19万局历史棋谱+教学书籍 |
| **视觉识别** | YOLO (规划中) | 现实棋盘识别 |

### 2.2 系统架构图

```
                    ┌─────────────────────────┐
                    │     Orchestrator        │
                    │  自适应决策（简单/复杂） │
                    └────────────┬────────────┘
                                 │
         ┌─────────────────────┼─────────────────────┐
         ▼                     ▼                     ▼
  ┌─────────────┐      ┌─────────────┐      ┌─────────────┐
  │  战术专家    │      │  战略专家    │      │  引擎专家    │
  │(TacticsAgent)│      │(StrategyAgent│      │(EngineAgent)│
  │工具:棋子攻防 │      │工具:局面战略 │      │工具:深度分析 │
  │      +走法  │      │      +走法对比│      │      +候选走法│
  └─────────────┘      └─────────────┘      └─────────────┘
                                 │
                    ┌────────────┴────────────┐
                    │      Synthesizer        │
                    │  综合三方结论 → 统一讲解 │
                    └─────────────────────────┘
```

### 2.3 数据流程

```
FEN输入 → 局面解析 → 标签检测(45个) → 张力检测(6种) →
Evidence Map生成 → Agent工具调用(最多3轮) →
Synthesizer综合 → LLM生成讲解 → 前端展示
```

## 三、核心功能模块

### 3.1 事实计算层

#### 3.1.1 标签检测体系（45个标签，9大层级）

| 层级 | 标签数 | 示例 |
|------|--------|------|
| 将杀困毙层 | 3个 | is_check, is_checkmate, is_stalemate |
| 捉子层 | 3个 | is_attack_unprotected, is_mutual_attack |
| 闪击抽将层 | 3个 | is_discovered_check, is_double_attack_with_check |
| 牵制串打层 | 2个 | is_pinned, is_cannon_double_attack |
| 标准杀法层 | 8个 | 马后炮、铁门栓、双车错等 |
| 子力状态层 | 2个 | piece_is_unprotected, cannon_has_platform |
| 走法质量层 | 6个 | move_is_blunder, move_is_capture等 |
| 战略评估层 | 5个 | controls_open_file, has_active_pieces等 |
| 引擎对齐层 | 3个 | engine_only_move, engine_best_by_margin等 |

#### 3.1.2 张力检测器（6种张力）
- 评估异常
- 威胁失衡
- 子力失衡
- 阶段异常
- 驱动Agent工具调用决策

### 3.2 Agent工具系统（10个工具）

#### 四类工具矩阵：

| 类别 | 工具 | 功能 |
|------|------|------|
| **棋子关系** | get_piece_attacks | 获取棋子攻击目标 |
| | get_piece_defenders | 获取棋子保护者 |
| | get_threats_to_piece | 获取威胁棋子的敌子 |
| | get_piece_relations | 综合棋子关系 |
| **走法分析** | analyze_move | 分析走法效果 |
| | compare_moves | 对比多个走法 |
| | get_forcing_sequence | 获取强制序列 |
| **引擎分析** | engine_deep_analysis | 引擎深度分析 |
| | engine_alternatives | 获取候选走法 |
| **战略分析** | analyze_position_strategy | 局面战略分析 |

#### 调用约束：
- 最多3轮调用，每轮最多3个工具并行
- 总耗时<5秒
- 每个工具有thinking过程反馈

### 3.3 多Agent并行架构

#### 三位专家角色：
- **战术专家 (TacticsExpert)**：专注子力关系和战术细节
- **战略专家 (StrategyExpert)**：专注全局战略和相位判断
- **引擎专家 (EngineExpert)**：专注解读引擎评估和候选走法

#### 自适应决策策略：
- 张力数量==0且开局：单Agent快速分析
- 张力≤2：单Agent+扩展轮次
- 张力≥3或CRITICAL或用户要求深度：多Agent并行
- 超时降级：2分钟后自动降级为单Agent

## 六、设计理念

### 6.1 神经符号AI架构
- **符号系统**：规则硬判定，100%准确，无幻觉
- **神经网络**：LLM负责表达和推理，不负责事实检测
- **Evidence Map**：锚定LLM输出，防止编造

### 6.2 教练式AI设计
```python
System Prompt核心要素：
- 你收到Evidence Map（事实锚点），必须基于此回答
- 所有事实必须来自Evidence Map或工具调用结果
- 不确定时说"需要进一步分析"，不要猜测
- 用"因为...所以..."的逻辑组织讲解
```

### 6.3 T0比赛优先战略
- 用规则脚本而非模型提取特征（100%准确，无幻觉）
- LLM只负责表达，不负责重建棋盘空间
- Evidence Map约束LLM，防止编造

## 十一、数据库设计（Neo4j知识图谱）

### 11.1 节点类型

| 节点类型 | 属性 | 用途 |
|----------|------|------|
| Game | game_id, event, date, players, result | 存储完整对局信息 |
| Position | position_id, fen, eval, move_number | 存储局面状态 |
| Move | move_id, uci, chinese, eval_delta | 存储走法信息 |
| Tag | tag_id, name, category | 45个战术标签 |
| Player | player_id, name, title, rating | 棋手信息 |
| Opening | opening_id, name, eco, moves | 开局库 |

### 11.2 关系类型

| 关系 | 起点 | 终点 | 说明 |
|------|------|------|------|
| CONTAINS | Game | Position | 对局包含的局面 |
| LEADS_TO | Position | Move | 局面可走的走法 |
| HAS_TAG | Move/Position | Tag | 战术标签关联 |
| PLAYED_BY | Game | Player | 对局棋手 |
| USES_OPENING | Game | Opening | 开局分类 |

## 十二、竞品分析

### 12.1 国内象棋AI产品对比

| 产品 | 定位 | 优势 | 劣势 | 与本项目差异 |
|------|------|------|------|--------------|
| **象棋旋风** | 竞技对弈引擎 | NNUE算法、特级大师水平、多次冠军 | 纯引擎无讲解、对普通学习者不友好 | 无教学功能 |
| **天天象棋** | 休闲娱乐平台 | 用户量大、多种玩法、社交功能 | 分析深度有限、讲解机械化 | 无深度讲解 |
| **象棋名手** | 专业分析工具 | 引擎强大、复盘功能 | 界面陈旧、无AI讲解 | 无智能讲解 |
| **人人象棋** | 在线对弈 | 真人对弈、复盘演练 | 缺乏教学引导 | 无教练式引导 |

### 12.2 国际LLM+Chess产品对比

| 产品 | 定位 | 优势 | 劣势 | 与本项目差异 |
|------|------|------|------|--------------|
| **LLM Chess** | LLM能力评测 | 测试LLM推理能力 | 纯评测工具、非教学产品 | 非教学导向 |
| **Chess Coach AI** | AI教练 | 实时反馈、可理解讲解 | 国际象棋、依赖LLM直接输出 | 无幻觉控制 |
| **ChatGPT Chess** | 通用AI | 覆盖面广 | 棋局理解差、经常幻觉 | 幻觉问题严重 |

### 12.3 本项目核心差异化优势

| 维度 | 传统引擎 | LLM产品 | 本项目 |
|------|----------|---------|--------|
| 分析准确性 | 高 | 低 | 高 |
| 讲解可理解性 | 低 | 中 | 高 |
| 零幻觉保证 | 高 | 无 | 高 |
| 教练式引导 | 无 | 低 | 高 |
| 中文语境优化 | 低 | 中 | 高 |
| 知识库支撑 | 无 | 无 | 高 |

### 12.4 创新点总结

1. **神经符号混合架构**
   - 竞品：要么纯引擎（无讲解），要么纯LLM（有幻觉）
   - 本项目：规则符号系统（100%准确）+ LLM表达层

2. **Evidence Map约束机制**
   - 竞品：LLM直接生成，容易编造
   - 本项目：事实锚点约束，LLM只能基于事实表达

3. **多Agent并行分析**
   - 竞品：单一分析视角
   - 本项目：战术/战略/引擎三专家并行，合成统一讲解

4. **教练式讲解风格**
   - 竞品：念坐标、"红方优势"
   - 本项目："因为红马踩着黑炮且黑炮无根，所以..."因果关系

5. **现代中式UI设计**
   - 竞品：传统界面或通用设计
   - 本项目：iOS 26 Liquid Glass + 墨韵青灯主题
