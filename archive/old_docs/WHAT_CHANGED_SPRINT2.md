# Sprint 2：我们做了什么？

> 用非技术语言解释给产品经理、项目经理和投资人

---

## 🎯 Sprint 2 的目标

**一句话概括**：建立"工具接口标准"，让系统可以随时切换真实引擎和知识库。

Sprint 1 搭好了房子框架，Sprint 2 的目标是：
- ✅ 定义工具标准（制定"插座规格"）
- ✅ 实现 Mock 工具（制造"假插座"）
- ✅ 重构应用使用标准接口（把"直连线"改成"插头"）

---

## 📋 我们具体做了什么？

### 🔌 1️⃣ **定义"工具标准"（统一接口）**

**问题**：Sprint 1 中，Gradio 应用直接写死数据，如果想用真实引擎，需要改很多代码。

**解决方案**：建立"统一接口标准"，就像制定国家标准插座：

#### 📦 三大工具接口

**1. 引擎工具（Engine）- "计算器"**
- **输入**：棋局文本（FEN）
- **输出**：
  - 最佳着法（例如：炮二平五）
  - 局面评分（例如：+0.3，红方优势）
  - 搜索深度（例如：20层）
  - 主要变例（后续几步棋）

**2. 知识图谱工具（KG）- "历史档案库"**
- **输入**：棋局文本（FEN）
- **输出**：
  - 历史胜率（例如：红方55%）
  - 开局名称（例如：当头炮开局）
  - 统计信息（例如：黑方常见应对是马8进7）

**3. 棋书检索工具（RAG）- "智能图书馆"**
- **输入**：查询文本（例如："炮开局"）
- **输出**：
  - 书名（例如：《橘中秘》）
  - 引用内容（例如："当头炮势如破竹"）
  - 相关性分数（例如：0.95）

---

### 🎭 2️⃣ **实现 Mock 工具（"假插座"）**

**问题**：真实引擎、数据库、向量库需要复杂的配置和数据准备，不能马上用。

**解决方案**：先做"模拟版"工具，确保接口设计合理。

#### 📦 Mock 工具示例

**Mock 引擎**：
```python
输入：初始局面 FEN
输出：推荐"炮二平五"，评分+0.3，深度20层
（这是预设的，不是真实计算的）
```

**Mock 知识图谱**：
```python
输入：初始局面 FEN
输出：历史胜率55%，开局名称"当头炮"
（这是预设的，不是真实查询的）
```

**Mock 棋书检索**：
```python
输入：查询"炮开局"
输出：《橘中秘》"当头炮势如破竹"，相关性0.95
（这是预设的，不是真实检索的）
```

**比喻**：就像装修房子，先把插座位置定好、电线布好，用一个假灯泡测试电路是否通畅。等真灯泡买回来，直接插上就能亮。

---

### 🔧 3️⃣ **重构 Gradio 应用**

**问题**：Sprint 1 的代码把数据写死在函数里，换数据就要改代码。

**解决方案**：改成"调用工具接口"，数据来源与界面解耦。

#### 📊 对比：Sprint 1 vs Sprint 2

**Sprint 1（硬编码）**：
```python
# 直接写死数据
bestmove = "炮二平五"  # 写死的
eval = "红方稍优 (+0.3)"  # 写死的
citations = ["[知识图谱] 胜率55%"]  # 写死的
```

**Sprint 2（调用接口）**：
```python
# 调用工具接口
engine = MockEngine()  # 工具
kg = MockKG()  # 工具
rag = MockRAG()  # 工具

engine_result = engine.analyze(fen)  # 从引擎获取
kg_result = kg.query(fen)  # 从知识图谱获取
rag_results = rag.retrieve(query)  # 从棋书检索获取

bestmove = engine_result.bestmove
eval = engine_result.score
citations = [kg_result.statistics, rag_results[0].content]
```

**效果**：
- ❌ Sprint 1：改数据 = 改代码
- ✅ Sprint 2：改数据 = 换工具（Mock → 真实）

---

### 🧪 4️⃣ **建立接口测试体系**

**问题**：怎么确保工具接口设计合理？怎么保证替换工具后不会出错？

**解决方案**：为每个工具接口编写自动化测试。

#### 📦 测试覆盖

**引擎接口测试**：
- ✅ 返回的数据类型是否正确？
- ✅ 初始局面能否正确分析？
- ✅ 自定义深度参数是否生效？

**知识图谱测试**：
- ✅ 返回的数据类型是否正确？
- ✅ 初始局面能否查询到数据？
- ✅ 无数据时是否能正确处理？

**棋书检索测试**：
- ✅ 返回的数据类型是否正确？
- ✅ top_k 参数能否限制数量？
- ✅ 相关性分数是否在 0-1 之间？
- ✅ 结果是否按相关性排序？
- ✅ 无匹配时是否返回默认结果？

**工具协同测试**：
- ✅ 三个工具能否一起工作？
- ✅ 能否组合成最终输出？

**效果**：运行 `pytest -q`，自动检查 33 项指标（Sprint 1: 21项 → Sprint 2: 33项）。

## 🚫 Sprint 2 **没有**做什么？

### ❌ 没有集成真实引擎

**现状**：推荐着法仍然是预设的，不是 Pikafish 引擎算出来的。

**原因**：需要下载 Pikafish 二进制文件，配置 UCI 协议通信。

**计划**：Sprint 2.1 会集成真实引擎。

---

### ❌ 没有连接真实知识库

**现状**：历史胜率和开局名称是预设的，不是从 Neo4j 数据库查询的。

**原因**：需要搭建 Neo4j 数据库，导入历史对局数据。

**计划**：Sprint 2.1 会连接真实数据库。

---

### ❌ 没有真实的棋书检索

**现状**：引用内容是预设的，不是从向量库检索的。

**原因**：需要准备棋书 PDF，构建向量索引。

**计划**：Sprint 2.1 会构建真实向量库。

---

### ❌ 没有实现 LangGraph Agent

**现状**：工具调用流程是硬编码的，不是 Agent 动态编排的。

**原因**：需要设计 Agent 状态机，定义节点和边的流转逻辑。

**计划**：Sprint 2.1 会实现 Agent 编排。

## 🚀 Sprint 2.1 要做什么？

Sprint 2 建好了"插座"，Sprint 2.1 要插入"真电器"：

### 🎯 Sprint 2.1 目标

把 Mock 工具替换成真实工具。

### 📦 Sprint 2.1 任务

#### 1️⃣ **集成 Pikafish 引擎**

**当前**：Mock 引擎返回预设数据
**目标**：真实引擎通过 UCI 协议计算

**需要的资源**：
- Pikafish 可执行文件
- UCI 协议通信代码
- 配置文件（引擎路径、默认深度等）

---

#### 2️⃣ **连接 Neo4j 数据库**

**当前**：Mock KG 返回预设统计
**目标**：从数据库查询真实历史数据

**需要的资源**：
- Neo4j 数据库实例
- 历史对局数据（PGN 格式）
- Cypher 查询脚本
- 数据导入脚本

---

#### 3️⃣ **构建 FAISS 向量库**

**当前**：Mock RAG 返回预设引用
**目标**：从向量库检索真实棋书内容

**需要的资源**：
- 棋书 PDF 文件
- Embedding 模型（BGE-M3）
- FAISS 索引文件
- 向量化脚本

---

#### 4️⃣ **实现 LangGraph Agent**

**当前**：工具调用流程硬编码
**目标**：Agent 动态编排工具调用

**需要的资源**：
- LangGraph 框架
- Agent 状态定义
- 节点和边的编排逻辑
- DeepSeek API Key（用于决策）

```
└── docs/                 # 文档
```

### 🎯 Pikafish 引擎放置

**Sprint 2.1 需要准备**：
1. 下载 Pikafish：https://github.com/official-pikafish/Pikafish/releases
2. 解压到 `data/engine/pikafish`（或 `pikafish.exe`）
3. 在配置中指定路径：
   ```python
   engine = PikafishEngine(path="data/engine/pikafish")
   ```

### 📚 棋书 PDF 放置

**Sprint 2.1 需要准备**：
1. 准备棋书 PDF 文件（确保版权合规）
2. 放到 `data/books/` 目录
3. 运行向量化脚本：
   ```bash
   python scripts/vectorize_books.py
   ```

### 🗄️ Neo4j 数据准备

**Sprint 2.1 需要准备**：
1. 安装 Neo4j 数据库
2. 准备 PGN 对局数据放到 `data/games/`
3. 运行导入脚本：
   ```bash
   python scripts/import_to_neo4j.py
   ```
